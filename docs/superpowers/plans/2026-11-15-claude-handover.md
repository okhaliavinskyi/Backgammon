## Текущий результат и границы

Приложение: React 19 + Vite (`apps/web`), Cloudflare Worker + Durable Objects (`worker`), движок (`packages/core`).

Последние явные пожелания реализованы:

- Доска **нигде не поворачивается**. Вертикальный бар и пункты сверху/снизу, обычное направление движения шашек.
- На портретном телефоне внешний формат доски фиксирован; не растягивать её на свободную высоту и не менять размеры/пропорции/положение без прямого запроса.
- Доска близко к шапке. Карточки игроков у нижнего края, управление между ними.
- Карточки следуют структуре референса **без аватаров**: полоса с шашкой и названием цвета, имя, индикатор хода/счёт, статистика, две ячейки реального времени.
- В центре — чат и быстрые реакции 👍 😂 🔥 🤝; полный набор остаётся в More. Чат работает в онлайне. В AI/local не рисуется неработающая кнопка чата.
- Видимый переключатель «Автоход» удалён. Сами настройки autoConfirm/autoRoll и их работа сохранены, доступны в настройках.
- Вверху справа — шестерёнка. Настройки открываются поверх игры, не закрывая комнату и не размонтируя доску.
- Пункты имеют скруглённые основания; номера контрастные.
- Обычная шашка имеет тонкую двухцветную каёмку. Доступная для хода — цветную обводку. Выбранная — толстую обводку, галочку/счёт стопки и усиленную тень. Исходный цвет выбранной шашки сохраняется.
- Цели — полупрозрачные шашки на реальном месте посадки; подсветка пункта мягкая.

## Особенно важно: что означает «место под шашку»

Последнее уточнение владельца: это **промежутки между скруглёнными основаниями соседних пунктов**, отмеченные красным на изображении, а не отдельное нарисованное кольцо.

Реализация в `Board.tsx`:

- Полная подложка доски рисуется градиентом рамки и, для wood, её текстурой дерева.
- Поверхность поля начинается на `TOP + R` и заканчивается на `BOTTOM - R`.
- Скруглённые цветные пункты накладываются сверху, поэтому в промежутках у их оснований виден **тот же материал рамки, что и под номерами**.
- Ранее добавленные 24 замкнутых кольца удалены. Не возвращать их по старым изображениям `selection-*`.
- `data-point-seat` теперь на пути пункта; это не отдельный круг. `data-field-surface` отмечает центральную поверхность поля.

Актуальный крупный пример: `handover-detail-seat-wood.png`.

## Геометрия, которую нельзя незаметно изменить

На 360×780, при пустом лотке:

| Показатель | Значение |
|---|---:|
| Верх доски | 66.1875 px |
| Зазор после шапки | 12 px |
| Ширина | 344 px |
| Высота | 431.953125 px |
| viewBox | `0 0 876 1100` |
| Нижний отступ HUD | 12 px + учёт safe area через CSS |

- `geom(1100)` — портретный телефон; `geom(800)` — остальные размеры. Поворотов и обратного поворота указателя нет.
- Поле заканчивается в x=852; рамка ещё24 единицы, поэтому ширина без пустой правой зоны876.
- Пустой лоток справа скрыт. При цели выноса или уже снятых шашках ширина возвращается к1000; вынос остаётся доступен. Размер контейнера согласован с viewBox, чтобы не получить letterboxing и неверные координаты указателя.
- Геометрия шашек: R=29; стеки пунктов максимум290 единиц. Не менять точки посадки ради обводки/теней.
- `mobile-hud` — три колонки: игрок /104px управление / соперник; `margin-top:auto` держит блок снизу.
- Настройки — native `<dialog>` с SettingsScreen. Escape, «Назад» и backdrop закрывают его. Четыре скорости на360px уложены в2×2 без горизонтального переполнения. Диалог не останавливает серверный таймер.

## Поведение игры, которое уже защищено

- По умолчанию autoRoll/autoConfirm=true; persist version1 мигрирует старую версию0.
- Окно отмены1200ms; удвоение2000ms; обычный автобросок450ms.
- `sent`, `paused`, `doubled` предотвращают повторную отправку и зависание после reconnect/error. После rejected move — ручное ✓, без автоматического повторения.
- Автобросок зависит от `g.conn`: после reconnect на той же seq/roll-фазе должен повторно запускаться.
- При единственной цели тап по шашке играет ход; при единственной подвижной шашке она автоматически выбрана.
- Димминг хранит legal-set только на время анимации фрагмента, очищается на чужом ходу. Отдельный `dimMovable` передаётся в BoardView.
- Порядок рисования сохраняется внутри стопки; поднимается целая локация, а не отдельный старый id.
- Призрак цели рисуется над шашками, считает шашки mover, а не чужой blot. Вынос учитывает половину лотка mover/viewer.
- Rejoin забирает только offline-seat после проверки пароля, меняет token; оба online → room_full. Сохранённый fallback-name комнаты живёт в localStorage, как token, переживает reload/новую вкладку.

## Как запустить и повторить проверки

Проверенная среда: Node22.23.1, npm10.9.8, Chrome. node_modules уже есть; не устанавливать новые зависимости.

Из корня:

```bash
npm run typecheck && npm test; echo EXIT=$?
npm run build; echo EXIT=$?
```

После build, в отдельном терминале:

```bash
cd worker
npx wrangler dev --port 8787
```

Не запускать два Wrangler с общей локальной SQLite-папкой одновременно. Во время ранней проверки на8788/8787 был SQLITE_BUSY; последующие финальные прогоны шли с одним сервером. Для этой передачи свой Wrangler остановлен после проверок.

При работающем8787:

```bash
NARDY_URL=http://127.0.0.1:8787 npx vitest run worker/test/integration.test.ts; echo EXIT=$?
node --experimental-strip-types apps/web/scripts/contrast.ts; echo EXIT=$?

NODE_PATH=~/.npm/_npx/9833c18b2d85bc59/node_modules node e2e/online.e2e.cjs /tmp/nardy-e2e; echo EXIT=$?

NODE_PATH=~/.npm/_npx/9833c18b2d85bc59/node_modules PREVIEW_ONLY=1 node e2e/online.e2e.cjs /tmp/nardy-preview; echo EXIT=$?
```

`PREVIEW_ONLY` — новый постоянный режим для повторения последних online-снимков, вместо одноразовых `/tmp`-скриптов. `PREVIEW_PREFIX` при необходимости меняет префикс файлов, по умолчанию `handover`. В режиме проверяются геометрия, undo, выбранная отметка, рамочная подложка, открытие/закрытие settings, сохранение hints и отсутствие горизонтального overflow. Позы и число целей могут немного отличаться: это реальные случайные кости.

Другие существующие режимы:

```bash
NODE_PATH=~/.npm/_npx/9833c18b2d85bc59/node_modules LAYOUT_ONLY=1 HINT_GATE=1 TASK=verification node e2e/online.e2e.cjs /tmp/nardy-layout; echo EXIT=$?
NODE_PATH=~/.npm/_npx/9833c18b2d85bc59/node_modules STATES_ONLY=1 node e2e/online.e2e.cjs /tmp/nardy-states; echo EXIT=$?
NODE_PATH=~/.npm/_npx/9833c18b2d85bc59/node_modules GHOST_ONLY=1 node e2e/online.e2e.cjs /tmp/nardy-ghost; echo EXIT=$?
```

LAYOUT_ONLY и STATES_ONLY используют AI/resume fixtures, поэтому там нет online-чата. Для текущего пользовательского вида нужен PREVIEW_ONLY. Старый VERTICAL_GATE больше не является требованием: поворот отменён.

Playwright находится в npx-cache, не в зависимостях проекта. В коде launch используется `{channel:'chrome'}`. Geometry TS напрямую strip-types не импортировать: нужны bundle через установленный esbuild и импорт полученного ESM. Код выхода читать у самой команды, без `| tail`.
