# План разработки

Каждый этап завершается проверкой (V). Следующий этап начинается только после зелёной проверки.

| # | Этап | Результат | Проверка (V) |
|---|---|---|---|
| 0 | Каркас монорепо | workspaces, tsconfig, линт-скрипты | `npm run typecheck` |
| 1 | Движок `core` — модель | типы, расстановки, путь игрока ↔ абсолютные пункты | unit-тесты маппинга и расстановки |
| 2 | Движок — генерация ходов | все легальные ходы, максимум очков, большая кость, бар, bear-off, голова, блок 6 | unit-тесты по каждому правилу |
| 3 | Движок — партия и матч | фазы, начальный бросок, кубик, Кроуфорд, очки, сдача | unit-тесты + fuzz «случайные партии до конца» |
| 4 | ИИ | оценка для двух вариантов, 3 уровня, решения по кубику | тест «ИИ против ИИ», 50 партий; Мастер выигрывает у Новичка > 70 % |
| 5 | Сервер | Worker, RoomDO, LobbyDO, протокол, часы, alarm, переподключение | интеграционный тест через локальный `wrangler dev` и 2 WebSocket-клиента |
| 6 | Клиент — каркас | роутинг, i18n, настройки, темы, `GameController` | сборка Vite |
| 7 | Клиент — доска | SVG-доска, шашки с анимацией, подсветка ходов, drag & drop, 3D-кости, стакан | визуальная проверка скриншотами Playwright |
| 8 | Клиент — экраны | главное меню, лобби, создание и вход, игра, итог, чат и эмодзи | e2e: две вкладки играют онлайн |
| 9 | Мобильное | встряхивание (DeviceMotion), вибрация, звук, PWA, вёрстка | эмуляция iPhone в Playwright |
| 10 | CI/CD | ci.yml (typecheck, тесты, сборка), deploy.yml (wrangler) | Actions зелёный |
| 11 | Анализ и ревью | самоаудит кода, безопасности и правил, исправления | `docs/REVIEW.md` |

## Структура репозитория

```
packages/core/      движок правил, ИИ, протокол (общий для клиента и сервера)
apps/web/           клиент React + Vite
worker/             Cloudflare Worker + Durable Objects, wrangler.toml
docs/               SPEC, PLAN, REVIEW, DEPLOY
.github/workflows/  CI и деплой
```

## Риски
- **Комбинаторика ходов на дублях** (до 4 шагов × 15 шашек): нужна дедупликация по итоговой позиции для ИИ и дерево префиксов для интерфейса.
- **Разрешение DeviceMotion на iOS** — только по жесту пользователя. Отдельная кнопка в настройках и при первом броске.
- **Hibernation в Durable Objects** стирает память объекта — всё состояние хранится в storage, а идентичность сокета — в `serializeAttachment`.
