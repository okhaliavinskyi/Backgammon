# Нарды онлайн — техническое задание (SPEC)

Версия 1.0 · статус: утверждено по итогам интервью

## 1. Цель

Браузерная игра в нарды (длинные и короткие) с двумя режимами:

1. **Онлайн с человеком** — live-комнаты (с паролем или без), публичное лобби, чат и эмодзи.
2. **Против ИИ** — три уровня сложности, работает офлайн (PWA), расчёт в Web Worker.

Целевые устройства — десктоп и телефон (портрет и ландшафт). На телефоне кости можно бросить встряхиванием устройства, с анимацией стакана, звуком и вибрацией.

## 2. Решения по итогам интервью

| Вопрос | Решение |
|---|---|
| Вариант правил | Длинные **и** короткие нарды, выбор при создании комнаты или партии с ИИ |
| Хостинг | Cloudflare Workers (статика + API) + Durable Objects (комнаты, лобби), деплой из GitHub Actions |
| Контроль времени | Таймер на ход **и/или** общий банк времени («шахматные часы») |
| Языки | RU + EN, по умолчанию язык браузера |
| ИИ | 3 уровня: Новичок / Любитель / Мастер |
| Визуал | Три темы: «Дерево», «Минимал», «Малахит»; все ассеты процедурные (SVG и CSS) |
| Игроки | Только ник, без регистрации; переподключение по токену |
| Доп. фичи | Лобби открытых комнат, чат и быстрые эмодзи, PWA |

## 3. Правила

Общее для обоих вариантов: 15 шашек у каждого, две кости, на дубле ход делается 4 раза.
**Обязательно использовать максимум очков.** Если можно сыграть только одну кость — играется бо́льшая (если сыграть можно любую из двух).
Выбрасывание (bear-off) разрешено, только когда все 15 шашек в доме (последняя четверть). Кость больше нужной разрешает снять шашку с дальнего пункта, только если дальше неё шашек нет.

### 3.1 Длинные нарды
- Все 15 шашек стартуют с «головы». Белые и чёрные начинают в противоположных углах и движутся в одном направлении вращения (против часовой стрелки).
- Боя нет. Пункт, где стоит хотя бы одна чужая шашка, закрыт.
- С головы за ход можно снять **одну** шашку. Исключение — первый бросок игрока: на 6-6, 4-4 и 3-3 можно снять две.
- Нельзя построить блок из 6 подряд занятых пунктов, если впереди него нет ни одной шашки соперника. Блок, обходящий «границу» пути соперника, ограничением не считается.
- Первым ходит тот, у кого выпало больше при броске по одной кости. Затем он бросает обе кости заново.
- Очки: обычная победа («ойн») — 1, **марс** (соперник не снял ни одной шашки) — 2.

### 3.2 Короткие нарды (backgammon)
- Стандартная расстановка: 2 шашки на 24-м пункте, 5 на 13-м, 3 на 8-м, 5 на 6-м. Соперник ходит навстречу.
- Одиночную шашку соперника («блот») можно побить, она уходит на бар. Пока на баре есть шашка, другими ходить нельзя — сначала ввод в дом соперника.
- Пункт с 2 и более шашками соперника закрыт.
- Первый ход: каждый бросает по одной кости, у кого больше — ходит этими двумя значениями. При равенстве — переброс.
- Кубик удвоения (опция комнаты, по умолчанию включён): предложить можно только перед своим броском, если кубик в центре или у тебя. Отказ — проигрыш текущей стоимости. Правило Кроуфорда в матчах.
- Очки: победа — 1, гаммон (соперник не снял ни одной) — 2, бэкгаммон (вдобавок есть шашка на баре или в доме победителя) — 3. Всё умножается на кубик.

### 3.3 Матч
Длина матча: 1, 3, 5 или 7 очков. Сдача партии отдаёт сопернику столько очков, сколько он получил бы, закончись партия прямо сейчас (марс и гаммон учитываются по текущей позиции, бэкгаммон при сдаче не засчитывается), умноженных на кубик.

## 4. Функциональные требования

### 4.1 Лобби и комнаты
- Создание комнаты: вариант, длина матча, таймер хода (выкл / 15 / 30 / 60 / 90 с), банк времени (выкл / 3 / 5 / 10 / 20 мин), кубик удвоения (только для коротких), пароль (необязательный), публичная или нет.
- Комната получает 6-символьный код и ссылку `/r/<код>`.
- Публичные комнаты без пароля и со свободным местом видны в лобби. Комнаты с паролем показываются с замком.
- Вход по коду или ссылке; при пароле — ввод пароля. Третий участник не допускается.
- Переподключение: токен игрока хранится в `localStorage`. При обрыве связи место держится 120 с, соперник видит статус «отключился». Часы при этом продолжают идти.
- Комната без активности удаляется через 30 минут.

### 4.2 Ход игры
- Бросок: кнопка или тап по доске, на телефоне — встряхивание. Опция «автобросок»: если удвоение не предлагается, кости бросаются сами.
- Кости генерирует **сервер** (`crypto.getRandomValues`). Клиент только анимирует результат.
- Подсказки: при выборе шашки подсвечиваются все допустимые пункты, включая составные ходы (сумма костей одной шашкой). Ход выполняется тапом по пункту или перетаскиванием.
- Ход можно отменять, пока он не подтверждён. Подтверждение — кнопкой «Готово» или автоматически (опция).
- Если допустимых ходов нет, игрок видит уведомление «Нет ходов», ход передаётся автоматически.
- Сервер полностью валидирует весь ход по тем же правилам из общего пакета.

### 4.3 Время
- Только таймер хода: по истечении сервер сам бросает кости и делает ход (уровень ИИ «Любитель»).
- Только банк: время убывает во время хода игрока. Когда банк исчерпан — поражение в матче.
- Оба: таймер хода работает как бесплатная задержка (delay), после неё убывает банк.

### 4.4 Чат
Текст до 200 символов, 8 быстрых эмодзи-реакций (всплывают над доской). Ограничение частоты: 1 сообщение в 700 мс.

### 4.5 Режим против ИИ
- Уровни: **Новичок** — случайный ход, слегка смещённый к хорошим; **Любитель** — жадная оценка позиции; **Мастер** — оценка + перебор 21 броска соперника (expectimax на 1 ход).
- Также доступна «игра вдвоём на одном устройстве» (hot-seat) — бесплатный побочный продукт той же архитектуры.
- В коротких нардах ИИ принимает решения по кубику: предлагает удвоение и принимает или отказывается по оценке шансов.

### 4.6 Настройки клиента
Тема, язык, звук вкл/выкл, скорость анимации (медленно / норма / быстро / мгновенно), автобросок, автоподтверждение хода, подсказки ходов вкл/выкл, бросок встряхиванием (на iOS — запрос разрешения), вибрация.

## 5. Нефункциональные требования
- Первый экран: JS ≤ 250 КБ gzip, без внешних шрифтов и картинок.
- 60 fps на анимациях шашек и костей: только `transform` и `opacity`.
- Расчёт хода ИИ «Мастер» ≤ 1,5 с на среднем телефоне.
- Доступность: управление с клавиатуры (Tab/Enter) по пунктам, `aria-label` у пунктов, контраст тем ≥ 4.5:1 для текста.
- Сервер авторитетен: клиент не может сделать нелегальный ход и не влияет на кости.

## 6. Технический стек

| Слой | Технология | Почему |
|---|---|---|
| Монорепо | npm workspaces, TypeScript 5.9 | Один набор правил для клиента и сервера |
| Движок | `packages/core` — чистый TS без зависимостей | Тестируется изолированно, работает в браузере, Worker и Durable Object |
| Тесты | Vitest; Playwright для e2e-смоука | Быстро, нативный TS |
| Клиент | React 19 + Vite, Zustand для состояния | Лёгкий бандл, быстрый dev |
| Графика | SVG-доска + процедурные текстуры (`feTurbulence`), 3D-кости на CSS | Чётко на любом DPI, ноль файлов-картинок |
| Звук | Web Audio API, синтез в реальном времени | Звук костей и шашек без аудиофайлов |
| ИИ | Web Worker | Интерфейс не подвисает во время расчёта |
| Сервер | Cloudflare Worker + Durable Objects (SQLite, WebSocket Hibernation) | Один объект на комнату — естественная модель; бесплатный тариф |
| Деплой | GitHub Actions → `wrangler deploy` | Пуш в main → прод |

## 7. Архитектура

```
Браузер ──HTTP──▶ Worker (fetch)
                   ├── /assets, SPA        → статические ассеты
                   ├── POST /api/rooms     → создаёт RoomDO, регистрирует в LobbyDO
                   ├── GET  /api/rooms     → LobbyDO.list()
                   └── GET  /api/rooms/:id/ws (Upgrade) → RoomDO
RoomDO: состояние партии (storage), сокеты (hibernation), alarm для таймеров
LobbyDO: список публичных комнат, обновляется RoomDO
```

Клиентская абстракция `GameController`: `LocalController` (ИИ и hot-seat) и `RemoteController` (WebSocket). Интерфейс игры не знает, с кем идёт игра.

### 7.1 Протокол (JSON по WebSocket)
Клиент → сервер: `hello{token?, name, password?}`, `roll`, `move{steps[]}`, `double`, `take`, `drop`, `resign`, `rematch`, `chat{text}`, `emoji{e}`, `ping`.
Сервер → клиент: `welcome{you, token}`, `state{room, game, clocks, serverNow}`, `rolled{dice}`, `moved{by, steps}`, `chat{…}`, `emoji{…}`, `error{code}`, `pong`.

## 8. Критерии приёмки
1. Тесты движка проходят: расстановка, генерация ходов, правило максимума, правило большей кости, бой и бар, bear-off, головное правило, блок из 6, подсчёт очков, кубик.
2. Двое в разных браузерах создают комнату с паролем, играют партию до конца, счёт отображается корректно.
3. Перезагрузка вкладки посреди партии возвращает игрока в ту же позицию.
4. Нелегальный ход, отправленный вручную через сокет, отклоняется.
5. ИИ доигрывает партию до конца на всех уровнях в обоих вариантах (автотест «ИИ против ИИ», 50 партий без ошибок).
6. На телефоне встряхивание бросает кости.
7. CI зелёный, деплой запускается при наличии секретов.
