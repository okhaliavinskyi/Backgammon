# /ship

> Пункты о своей ветке, checkout main и `--no-ff` применяются только к выбранной
> проектом worktree-модели. Для shared-main и PR-модели следовать CLAUDE.md
> проекта; не запускать другую модель автоматически.

1. **В своей ветке.** Забрать чужое, разрешить конфликты у себя:
   ```
   git merge main
   npm test
   ```
   Запомнить число тестов — сверять после мерджа.

2. **Самоаудит.** Ответить на четыре вопроса `stop-selfaudit.mjs` — поимённо,
   файл и строка на пункт: дубли, мёртвый код, минусы построенного, что
   вычистить. Ответ идёт в описание PR, не только в чат. Отгрузка без него —
   отгрузка того, что никто не пересмотрел.

3. **В worktree с main.**
   ```
   git status
   git merge --no-ff <ветка>
   npm test
   ```
   Число тестов должно совпасть с шагом 1. Меньше — кто-то откатил ref, а не
   «Already up to date».

4. **Ворота.** `GATES.md` закрыт: у каждых ворот стоит EVIDENCE с датой и кодом
   возврата, у выбирающих ворот — контроль на ложное срабатывание.

5. **Деплой и прибирание.**
   ```
   git branch --contains <sha ветки> | grep main   # не верить "Already up to date"
   git branch -d <ветка>                            # именно -d, никогда -D
   ```
   `-d` отказывает в двух случаях, и оба означают «остановись и посмотри»:
   в ветке есть коммиты вне main, или её держит чужой worktree.

6. **Следующая работа — новая ветка от свежего main**, не продолжение смерженной.

Пуш и деплой выполняются по CLAUDE.md проекта и только со слова владельца.
Наличие pre-push-guard определяется проектным opt-in.
